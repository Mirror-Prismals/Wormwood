WORKSTATION OPTICAL FRAME ABI, revision 1

workstation.shared.glsl is the single numerical source. Run generate_workstation.py
beside it to update WGSL, desktop GL 330, GLES 300, and Vulkan 450 frontends.

All positions and distances are metres in a shared +Z-up optical scene. The
visible control table faces +Z. All optical RGB values are scene-linear Rec.709.
Only final display output is sRGB encoded. Do not apply another gamma transform.

Vertex input remains two vec4s: clip position and unused generic scene data.
The geometry submitted for this pipeline is a fullscreen quad. Primary and
secondary rays intersect the actual deformed panel planes from the frame; this
is a 3D material evaluation, not a shaded flat panel image.

WGSL group0 binding0: existing SceneVertex storage (vertex stage).
WGSL group0 binding1: readonly array<vec4<f32>> optical frame and immutable LUT.
Vulkan set0 binding1: existing SceneVertex storage (vertex stage).
Vulkan set0 binding0: optical frame/LUT storage (fragment stage).
GL/GLES: existing position/vertexData attributes; workstationData sampler2D is
RGBA32F, 256 texels wide. Integer texelFetch maps index to (index%256,index/256).

First 256 vec4 rows are the optical frame. Three dynamic floor visibility fields
follow, each EDGE squared vec4 rows (EDGE=64 gives 12288 field rows).
Immutable native OCIO LUT follows the frame plus fields; row7 gives its offset.

  2 cameraRight.xyz, halfWidthMetres

Floor fields store one cosine/emitter-weighted RGB visibility per light, with
sixteen actual area-light connections at each grid point. Grids are consecutive,
row-major, x fastest; sample positions include both domain endpoints:
  x=minimumX+spanX*column/(EDGE-1), y=minimumY+spanY*row/(EDGE-1).
The shader bilinearly filters each light's visibility and applies it to the
four view-dependent area-BRDF quadrature points. This aggregate visibility is an
explicit lighting approximation; it retains the floor's authored roughness and
gem material. Outside the field, direct visibility intersections remain active.
The field must update whenever its panel/light/floor geometry changes.

The host seals row255.w after all packet writers (including timeline).
Optional retained-image host protocol: row255.w=-8192 requests deferred CPU
floor-field construction; rows256..12543 are finite placeholders in that host
packet. Every original-renderer/backend consumer resolves the exact current
field before shading. The retained WebGPU compositor may defer while drawing
only resident radiance; before a bake, explicit lighting refresh, unsupported
state fallback or no-input settle refresh, it resolves the most recent packet.
Shaders do not read this marker. Captured optical evidence always materializes
the field. WORMWOOD_WORKSTATION_DEFER_FLOOR=1 selects this optional protocol.

Integrator limits
This is a bounded deterministic real-time transport integrator using the authored
material. It is not Cycles pixel equivalence. It traces all four stones, exact
Fresnel reflection/refraction, total internal reflection, and per-segment volume
absorption. The sample and bounce/event limits are explicit. Terminal exterior leaves are
resolved at their parent surface to avoid allocating/scanning a pending ray.
The event budget therefore counts retained transport work, not those terminal
studio lookups. Surface-depth and minimum-throughput cutoffs remain unchanged.
The16-entry queue remains available for branches that hit other stones; states
are48bytes with scalar cached priority. Energy below the
cutoff or beyond the path budget is discarded, never replaced with painted light.
The floor uses correlated GGX plus diffuse direct area quadrature, constant world
illumination, and approximate transmission shadows. Shadow attenuation and
exit Fresnel use the actually refracted interior path; connection back to the
sampled emitter still omits the specular boundary-value solve. Focused caustics and general
scene diffuse global illumination are not reproduced. Actual device visual and
performance validation are separate from shader compiler validation.

allows height_m on notes, with one height and center per pitch. The existing
pitch-group Y bounds enclose center +/-0.6*height; the shader recovers that
pitch's height from (high.y-low.y)/1.2. Header234.y remains the maximum height
for whole-field bounds. Dynamic and immutable addresses/capacity do not move.
PianoKeyLayout.rs supplies the physical projection and key-front dimensions.
Piano camera composition preserves row9.z, retains opaque toolbar/keys and
uses bounded film transmittance for source-over composition inside the field.
